# Спецификации проекта (Spec-Driven Development)

> Сначала формально описываем, что и как должна делать система, — потом пишем код.

В этой папке живут спецификации: формальные описания требований, контрактов
и архитектурных решений проекта `async_parser`. Каждая спецификация — источник
правды для реализации: прежде чем менять код, мы меняем (или создаём)
спецификацию.

## Структура

| Путь                 | Назначение                                                  |
| -------------------- | ----------------------------------------------------------- |
| `GENERAL.md`         | Основы SDD: принципы, правила, жизненный цикл спецификации  |
| `GLOSSARY.md`        | Единая терминология проекта (shared vocabulary)             |
| `CONTEXT.md`         | Актуальное состояние системы (AS-IS)                        |
| `ADR.md`             | Журнал архитектурных решений (Architecture Decision Records)|
| `TEMPLATES/`         | Шаблоны для новых спецификаций                              |
| `specs/`             | Фактические спецификации (нумерованные файлы)               |

## Жизненный цикл спецификации

1. **draft** — черновик, идею ещё нельзя реализовывать;
2. **review** — черновик вынесен на ревью;
3. **approved** — утверждена, можно создавать задачи в `TODO.md`;
4. **implemented** — код реализован, тесты зелёные;
5. **done** — критерии приёмки выполнены и подтверждены.

Подробные правила — в [`GENERAL.md`](./GENERAL.md).
